# TermMosaic documentation site

Source for **https://serkanalgur.github.io/termmosaic.github.io/** — the
documentation site for
[TermMosaic](https://github.com/serkanalgur/termmosaic), a terminal UI
framework for Go.

Built with Hugo and deployed by GitHub Actions. There is no local build step:
push to `main` and the workflow publishes.

## What is here

| Path | What it is |
|---|---|
| `content/` | All pages. 70 Markdown files. |
| `content/widgets/` | **24 widget pages, one per widget.** Generated — see below. |
| `content/adr/` | The 10 Architecture Decision Records, **copied verbatim**. |
| `content/concepts/`, `content/guides/`, `content/getting-started/` | Hand-written. |
| `layouts/shortcodes/widget-capture.html` | Embeds a widget's captures at three widths. |
| `static/captures/` | **Generated by the framework repo. Do not hand-edit.** |
| `scripts/` | Generators and validators, all runnable locally. |
| `hugo.toml` | Site config. `baseURL` must stay `https://serkanalgur.github.io/termmosaic.github.io/` (with the trailing slash — without it Hugo resolves `/` to the domain root). |

## The captures are generated, and that is the point

Every widget screenshot on this site is a **real render**, not a mock-up. They
come from `cmd/capture` in the framework repo, which drives each widget through
the same headless path the tests use and writes the resulting **cell grid** to
plain text and HTML.

Two consequences worth knowing:

1. **A page cannot show output the code does not produce.** If a widget changes,
   the captures change, and CI fails until they are regenerated.
2. **They are not screenshots of a terminal.** There is no browser TTY and no
   wasm build. They cannot show interaction, resizing, timing, or how a real
   terminal renders them. Braille and Block Elements may misalign in a web
   font — which is why every capture ships a plain-text version beside the
   colour one, and why the site says so.

To regenerate after a framework change:

```bash
cd ../termmosaic
go run ./cmd/capture            # writes into ../termmosaic.github.io/static/captures
go run ./cmd/capture -check     # verify determinism without writing
```

Then commit the changed files here.

## Widget pages are generated

`content/widgets/*.md` is produced by `scripts/gen_widgets.py` from
`static/captures/index.json` plus hand-written prose in
`data/widget_prose.json`.

They are **committed**, not git-ignored, so that reviewing a widget page in the
repository shows the whole file rather than a generator's output.

To regenerate after changing the prose:

```bash
python3 scripts/gen_widgets.py
git diff content/widgets/     # read the diff — this is user-visible content
```

Two guards stop a widget being silently left out of the docs:

- the generator fails if `index.json` and the prose file disagree;
- `scripts/check_captures.sh` fails if any widget lacks a capture.

## Checks

All three run in CI before Hugo is invoked, so a content mistake never reaches
a deploy:

```bash
pip install PyYAML
python3 scripts/check_frontmatter.py    # 70 pages, TOML/YAML/JSON
bash    scripts/check_captures.sh       # 24 widgets, 3 widths, no failure markers
bash    scripts/check_verbatim.sh       # ADR/STATUS/CHANGELOG match the framework
python3 scripts/check_links.py          # every internal link resolves (after hugo)
```

`check_verbatim.sh` guards the verbatim copies. `content/adr/` holds copies of the
framework's ten ADRs, `STATUS.md`, `CHANGELOG.md` and `SITE-PLAN.md` — summarising
them would create a second source of truth that drifts. Run it with `--sync` to
re-copy; CI fails the deploy if they have drifted.

"Verbatim" means the body is unchanged. The site copies carry Hugo front matter
(title, weight, `toc`) and drop the framework file's leading `#` heading, because
Hugo uses the file name as the page title. The checker compares with both removed,
and `--sync` re-applies the front matter, so the two can never disagree.

`check_frontmatter.py` accepts TOML, YAML and JSON because Hugo does, and the
site is written in YAML — a TOML-only parser reports every page as broken.

## Editing

- **Concepts, guides, FAQ, limitations:** edit the Markdown directly.
- **Widget pages:** edit `data/widget_prose.json`, then re-run the generator.
  Editing a generated page directly means your change is lost on the next run.
- **ADRs:** copied verbatim from the framework repo's `docs/adr/`. They are
  **not summarised** — a summary would be a second source of truth that drifts.
  Re-copy when the framework's ADRs change.

## Adding a widget

1. Add the widget to the framework repo, with a registry entry in
   `internal/docsgen/registry.go` giving it a realistic demo state.
2. `go run ./cmd/capture` and commit the new captures.
3. Add prose for it in `data/widget_prose.json`, then
   `python3 scripts/gen_widgets.py`.
4. The framework's own tests fail if a new widget has no registry entry, so
   step 1 cannot be forgotten.

## Deploying

Push to `main`. `.github/workflows/deploy.yml` validates the content, builds
with Hugo (extended), and publishes to GitHub Pages.

The Go version is pinned to 1.23 deliberately: raising that floor is what would
unpin `golang.org/x/term` in the framework repo.
